# MMY-ActionFileSync UI 重构开发计划

## 1. 结论

建议把当前“左右两棵文件树 + 独立动作复选区 + 底部双预览”的界面，重构为一个面向任务的桌面工作台：

- 顶部固定显示“来源：新动作目录 → 目标：SVN 工作目录”，用文字、图标语义和不同强调色共同区分，避免只靠左右位置判断。
- 左侧使用一张统一的“动作差异清单”，动作目录是默认浏览和选择单位；帧文件仅在展开动作时按需显示。
- 右侧常驻两个并排动画预览，保持同一动作、同一播放进度、同一缩放和位移，直接对比来源与目标。
- 底部固定显示本次已选动作、文件数、大小和传输按钮，做到“清单勾选范围 = 预览范围 = 实际传输范围”。
- 初次扫描默认不勾选，避免误传；用户可单选 `idle`、多选任意动作、选择当前筛选结果，或展开动作后排除个别文件。

这套布局优先解决三个问题：来源与目标不再混淆、差异文件不再铺满主界面、更新单个动作不再需要“全不选后再找一个复选框”。

## 2. 当前项目分析

### 2.1 当前界面结构

当前主窗口在 `views/main_window.py` 中使用单列纵向布局，依次放置：

1. 左右目录树 `ComparePanel`
2. 动作筛选复选区 `ActionFilterPanel`
3. 传输操作与两条进度条 `TransferPanel`
4. 左右动画预览 `PreviewPanel`

窗口默认和最小尺寸都为 `600 × 800`。在这个宽度内，两棵三列树各分到约一半宽度，而动画画布又要求最小高度 350 px，信息区之间会互相挤压。

### 2.2 三个主要体验问题的根因

#### 问题 A：左右区域容易混淆

- 两侧目录树的形状、列名和内容高度相同，主要依靠标题“新文件夹列表 / SVN 文件夹列表”和浅色行背景区分。
- “仅左侧 / 仅右侧”是实现视角，不是用户任务视角。用户真正关心的是“新增待传 / 内容已变化 / 目标独有 / 已一致”。
- 目录选择、文件树和预览各自重复“左/右”概念，缺少持续可见的固定传输方向。
- 不同状态在两侧使用不同底色，同一状态的视觉含义不稳定。

#### 问题 B：全部文件有差异时列表过长

- `ScanService` 同时建立目录节点和每一帧图片节点，`ComparePanel` 再把它们全部放入左右树。
- “只看差异项”只隐藏一致项，并不会把同一动作的几十或几百帧聚合起来。
- 左右树展示的是同一组相对路径，屏幕宽度被重复信息占用，真正用于纵向浏览动作的空间反而不够。
- 现有模型会一次性创建全部 `QStandardItem`，大量帧文件时刷新和筛选也会变重。

#### 问题 C：只更新一个 `idle` 操作繁琐

- 动作选择在文件树之外的独立滚动区，用户需要先“全不选”，再寻找 `idle`，然后回到树或预览确认。
- 行高亮仅表示“当前预览”，复选框才表示“将要传输”，两种选择不在同一位置。
- `_refresh_tree_display()` 把空选择转换为 `None`，导致“复选框全部不选”时树又显示全部动作，但传输范围仍为空，视觉范围与实际范围不一致。
- `_get_checked_action_paths()` 会收集动作下所有差异节点，再由传输服务递归展开和去重。结果通常可用，但选择单位不清晰，也不利于在动作内部排除单个文件。

### 2.3 实施前应一并处理的代码问题

- `MainController.on_node_expanded()` 使用了不存在的 `compare_panel.right_tree / left_tree`，应改为新模型的单表展开逻辑，或在过渡期修正为 `right_side / left_side`。
- `views/compare_panel.py` 内还有一份未被控制器使用的 `TransferPreviewDialog`，与 `views/transfer_preview_dialog.py` 重复，应只保留独立文件中的实现。
- `TransferPanel.append_log()`、`set_file_started()`、`set_stats()` 和 `reset_actions()` 目前为空实现；新版应改为紧凑状态栏和可展开的任务详情，而不是保留无反馈接口。
- 动作名称目前通过 `relative_path.split('/')[1]` 推断，对目录层级有隐含假设。新版应在扫描/映射阶段明确生成 `action_id`、`action_name` 和动作根路径。

## 3. 推荐版面

### 3.1 桌面主布局

建议默认窗口 `1440 × 900`，最小窗口 `1100 × 720`，主体使用可拖动的 `QSplitter`：

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ MMY Action File Sync                    扫描状态        刷新  设置          │
├────────────────────────────────────────────────────────────────────────────┤
│ 来源｜新动作目录  D:/.../export    ───────→    目标｜SVN  D:/.../trunk     │
├───────────────────────┬────────────────────────────────────────────────────┤
│ 动作差异清单          │  来源预览｜新动作       目标预览｜SVN             │
│ 待更新  新增  不同... │ ┌──────────────────┐ ┌──────────────────┐         │
│ 搜索 idle             │ │                  │ │                  │         │
│                       │ │   同步动画播放   │ │   同步动画播放   │         │
│ □ attack  内容变更    │ │                  │ │                  │         │
│ ☑ idle    内容变更    │ └──────────────────┘ └──────────────────┘         │
│   ▸ 48 帧 / 12.4 MB   │ 帧 18/48  512×512      帧 18/48  512×512          │
│ □ jump    新增待传    │ 播放/暂停  帧滑杆  缩放  位移  差异闪烁           │
│ □ run     已一致      │                                                    │
│ ...                   │                                                    │
├───────────────────────┴────────────────────────────────────────────────────┤
│ 已选 1 个动作 · 48 个文件 · 12.4 MB       清空选择   传输预览   开始传输 │
└────────────────────────────────────────────────────────────────────────────┘
```

推荐初始分栏比例为清单 38%、预览 62%。用户可以拖动分隔条；应用记忆上次比例。

### 3.2 来源与目标的区分规则

不要继续使用“左侧 / 右侧”作为主要名称，统一采用：

- `来源｜新动作目录`：蓝色顶部标识线，图标使用“导入/文件夹”，只读角色标签显示“将从这里读取”。
- `目标｜SVN 工作目录`：橙色顶部标识线，图标使用“仓库/文件夹”，只读角色标签显示“将覆盖到这里”。
- 两者之间始终显示单向箭头和“复制到”，不提供反向传输按钮。
- 颜色只做增强，所有状态同时使用文字和图标，避免仅靠颜色表达。
- 预览标题、空状态、错误提示都使用“来源 / 目标”，不再使用“左 / 右”。

### 3.3 动作差异清单

动作清单使用一棵树，但默认只显示动作级行。推荐列：

| 列 | 内容 | 说明 |
| --- | --- | --- |
| 选择 | 复选框 | 决定实际传输范围；父级支持半选状态 |
| 动作 | 动作名与展开箭头 | 单击行只切换当前预览，不自动勾选 |
| 状态 | 新增待传 / 内容变更 / 已一致 / 目标独有 | 使用任务语义 |
| 变化 | `48 帧 · +3 / -1 / ~5` | 聚合显示新增、缺失、变更数量 |
| 大小 | 待复制的数据量 | 右对齐 |

默认视图只显示“可传输差异”，即来源存在且状态为 `only_left` 或 `different` 的动作。用户展开某个动作后，才创建并显示帧文件子项。

顶部工具建议：

- 状态分段筛选：`待更新`、`新增`、`内容变更`、`已一致`、`全部`。
- 搜索框：按动作名和相对路径过滤，输入 `idle` 后只显示匹配动作。
- `全选当前结果`、`清空选择`、`仅勾选高亮动作`，并支持 `Ctrl/Shift` 多行高亮和空格批量切换勾选。
- 数量摘要：例如“6 个待更新动作，218 个文件”。

### 3.4 自由选择传输范围

选择规则必须明确且可预测：

1. 扫描完成后默认不勾选任何动作。
2. 勾选动作目录时，默认包含该动作下所有可传输差异文件。
3. 展开动作后可以取消某个文件；父动作显示半选状态。
4. 搜索和状态筛选只改变“看见什么”，不改变已经勾选的内容。
5. “全选当前结果”只勾选当前筛选后的可见动作。
6. 单击行改变当前预览；复选框改变传输范围，两种状态样式明显不同。
7. 底部始终显示精确的动作数、文件数、总大小；点击摘要可查看已选列表。
8. 传输预览对话框允许最后一次取消某个动作或文件，并实时重算数量与大小。

`idle` 的最短操作路径应为：在搜索框输入 `idle` → 单击行确认双预览 → 勾选该行 → 传输预览 → 开始传输。也可以高亮 `idle` 后直接使用“仅勾选高亮动作”；多个动作可通过 `Ctrl/Shift` 一次高亮后批量勾选。

### 3.5 双动画预览

双预览继续并排保留，并增强为真正的对比视图：

- 两侧共享播放/暂停、时间轴、帧索引、缩放和 Y 轴位移。
- 切换动作后，两侧从第 1 帧同步开始；帧数不同时按归一化进度对齐，并显示各自帧号。
- 来源缺失或目标缺失时，缺失侧保留同尺寸画布，显示明确空状态，不让布局跳动。
- 每侧标题固定显示角色、动作名、尺寸和帧数。
- 提供“并排 / 叠加闪烁”两种模式；叠加模式作为第二阶段功能，不阻塞第一版。
- 文件路径移入可展开的详情行，避免长路径长期占用预览高度。

### 3.6 传输状态

空闲时底部栏只显示选择摘要与主操作。传输开始后原位切换为：

- 当前动作和文件名
- 单条总进度（默认），点击后展开当前文件进度和失败详情
- 成功、失败、跳过计数
- 完成后显示“重新扫描结果”，保留失败项入口

不建议在主界面长期放两条空进度条。它们占用垂直空间，但空闲阶段没有决策价值。

## 4. 数据与组件设计

### 4.1 新的展示模型

建议新增动作级视图模型，不直接让 UI 解析路径层级：

```python
@dataclass
class ActionDiffItem:
    action_id: str
    action_name: str
    relative_path: str
    status: str
    source_node: TreeNode | None
    target_node: TreeNode | None
    changed_files: list[FileDiffItem]
    transfer_file_count: int
    transfer_size_bytes: int
```

选择状态建议保存“明确选中的文件相对路径集合”，动作复选框只是该集合的聚合视图。这样筛选、展开/折叠和模型重建不会意外改变传输范围。

### 4.2 推荐组件拆分

| 组件 | 职责 | 处理方式 |
| --- | --- | --- |
| `MainWindow` | 顶部路径栏、主分割器、底部任务栏 | 重构 |
| `SourceTargetBar` | 来源/目标路径、方向、刷新状态 | 新增 |
| `ActionDiffPanel` | 筛选、搜索、动作树、勾选 | 替换 `ComparePanel` 和 `ActionFilterPanel` 的主职责 |
| `ActionDiffModel` | 动作聚合、懒加载文件行、三态勾选 | 新增 |
| `PreviewPanel` | 双预览与同步控制 | 保留并增强 |
| `TransferSummaryBar` | 已选摘要、进度、主操作 | 替换当前 `TransferPanel` 布局 |
| `TransferPreviewDialog` | 最终范围确认与排除 | 保留并增强，删除重复定义 |

### 4.3 状态映射

| 内部状态 | 新 UI 文案 | 默认可传输 |
| --- | --- | --- |
| `only_left` | 新增待传 | 是 |
| `different` | 内容变更 | 是 |
| `same` | 已一致 | 否 |
| `only_right` | 目标独有 | 否，且需要明确提示不会删除 |
| `unknown` | 无法判断 | 否 |

## 5. 分阶段实施

### 阶段 1：统一信息模型与选择逻辑

- 增加动作级聚合模型和稳定 `action_id`。
- 把传输选择从复选框控件状态迁移到独立状态集合。
- 让传输任务直接从选中文件集合生成，避免同一动作下多层节点重复递归。
- 增加模型单元测试：动作聚合、状态计数、三态勾选、筛选不丢选择、任务去重。

验收：可通过代码测试证明任意动作/文件组合最终只生成一次传输项。

### 阶段 2：主界面重排

- 新增来源/目标路径栏和明确方向标识。
- 用单动作清单替换左右树和独立动作筛选区。
- 使用 `QSplitter` 建立“动作清单 / 双预览”主布局。
- 将空闲传输区压缩为底部摘要栏。

验收：在 `1440 × 900` 下无需滚动主窗口即可看到不少于 18 个动作行和两块完整预览；在 `1100 × 720` 下无控件重叠。

### 阶段 3：预览同步与传输确认

- 增加共享播放/暂停和帧滑杆。
- 帧数不同时实现归一化进度映射。
- 传输预览支持取消动作/文件并重算总量。
- 补齐任务状态、错误详情和完成反馈。

验收：同一动作两侧预览始终保持同一进度；预览对话框的最终选项与实际复制文件完全一致。

### 阶段 4：性能与可用性完善

- 动作列表先聚合，文件子项按展开懒加载。
- 使用 `QSortFilterProxyModel` 处理搜索和状态筛选。
- 记忆窗口尺寸、分栏比例、最近路径和预览参数。
- 可选增加叠加闪烁对比、键盘多选和右键定位到资源管理器。

验收：数百个动作、数万帧文件场景下，首次列表渲染不创建全部文件行，搜索和勾选保持流畅。

## 6. 测试清单

- 来源和目标路径交换时，方向和风险提示正确。
- 仅来源动作、内容不同动作、目标独有动作、已一致动作的文案和可选性正确。
- 搜索 `idle` 后可在 4 次以内完成单动作传输确认。
- 全不选时，清单仍按筛选条件显示，但底部明确为“未选择任何文件”，传输按钮禁用。
- 已勾选动作在切换筛选、搜索、折叠和刷新后按规则保留或给出失效提示。
- 展开动作并排除文件后，父级为半选，汇总数量和传输预览同步变化。
- 两侧帧数相同和不同时，播放、拖帧、缩放、位移均保持可比较。
- 目标侧缺失时，右预览显示“目标尚无此动作”，来源动画仍可播放。
- 传输失败时，成功项与失败项可追踪，重新扫描不会静默掩盖失败。
- `1100 × 720`、`1440 × 900`、150% Windows 缩放下无文字截断和控件重叠。

## 7. 实施结果

本计划已在本地工作区完成首轮实现：

- 新增 `ActionDiffItem` / `FileDiffItem` 与 `ActionDiffService`，动作名称不再由控制器固定解析路径层级。
- 传输选择保存为明确的文件相对路径集合，筛选、搜索和折叠不会改变选择范围。
- 新增来源/目标路径栏，固定表达“新动作目录 → SVN 工作目录”的单向复制关系。
- 用单一动作差异清单替换主流程中的左右双树和独立动作复选区。
- 动作文件在展开时才创建行，支持动作级全选、三态显示和文件级排除。
- 双预览改为共享播放进度，支持帧滑杆、缩放、位移、并排和差异闪烁模式。
- 传输预览支持取消动作或单个文件，并实时重算动作数、文件数和大小。
- 底部传输栏已补齐选择摘要、单条总进度、当前文件、统计和可展开日志。
- 修复 PySide6 6.11 中错误访问 `dialog.Accepted` 导致确认窗口关闭后传输未启动的问题，统一使用 `QDialog.DialogCode.Accepted`。
- 传输开始时自动展开带时间戳日志；移除 `copystat()` 时间戳回写，目标文件保留实际覆盖时间。
- 修正异步预览结果覆盖当前动作、传输错误提前解锁界面等流程问题。
- 增加 MIT License、UTF-8 README、`.gitignore` 和核心服务自动化测试。
- 增加 GitHub Actions，在 `main` 分支推送和拉取请求中安装完整依赖并运行编译及 Qt 离屏测试。

保留的兼容文件 `views/compare_panel.py`、`views/compare_tree_panel.py`、`views/action_filter_panel.py` 和 `views/path_selector_panel.py` 已不再进入主窗口流程。考虑到删除属于高风险操作，本轮未直接删除，后续可在确认无外部引用后清理。

对应的可交互版面报告见同目录 `MMY-ActionFileSync_UI重构方案报告.html`。
