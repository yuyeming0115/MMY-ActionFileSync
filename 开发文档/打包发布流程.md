# MMY-ActionFileSync 打包发布流程

## 概述

使用 PyInstaller 把应用打包为单文件 exe（onefile + windowed）。打包脚本 `build_exe.bat` 每次构建都会在 `releases/` 下生成按“版本号_时间戳”命名的独立目录，历史版本全部保留，支持随时回退到旧版本。

## 使用方式

双击 `build_exe.bat` 即可。脚本会依次：

1. 检查/创建项目虚拟环境 `.venv`；
2. 安装 `requirements.txt` 依赖；
3. 检查并按需安装 PyInstaller；
4. 读取版本号并生成构建时间戳；
5. 打包 exe 到发布目录，并写入 `build_info.txt`。

## 发布目录结构

```text
releases/
├─ v0.2.5_20260929_104213/
│  ├─ MMY-ActionFileSync.exe
│  └─ build_info.txt
├─ v0.2.5_20260928_175306/
└─ ...
```

`build_info.txt` 记录 `app`、`version`、`build_time`、`git_commit`，用于辨认每个发布目录的来源。

## 版本管理规则

- 版本号单一来源：`utils/app_info.py` 的 `APP_VERSION`；窗口标题从该模块读取（`views/main_window.py`），发布目录名由打包脚本读取同一模块生成。
- 发新版本时只修改 `APP_VERSION`（如 `0.2.5` → `0.3.0`），目录名与界面版本号自动保持一致。
- 时间戳格式 `yyyyMMdd_HHmmss`，由 `utils/build_stamp.py` 生成；同版本重复打包不会互相覆盖。
- `releases/` 已加入 `.gitignore`，不进入版本库。

## 已知注意事项

- 不要给 PyInstaller 传以反斜杠结尾的带引号路径参数（如 `--specpath "D:\path\"`）：`\"` 会被 C 运行时当作转义引号，破坏后续参数的引号配对，导致 `main.py` 等参数丢失。脚本内已规避并用注释说明。
- bat 内嵌 `python -c` 的引号/百分号转义易碎，版本号与时间戳改由 `utils/build_stamp.py` 输出、bat 经临时文件读回，不再内嵌代码。
- bat 文件保持无 BOM；中文只允许出现在注释行，活动命令行一律使用 ASCII，避免代码页问题。
